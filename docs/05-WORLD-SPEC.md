# POLIS — World Specification

**Version:** 1.0
**Owner module:** `polis/world/`
**Tables owned:** `districts`, `places`, `tiles`, `place_paths` — defined in `03-DATA-MODEL.md §3`. This document does not redefine them; it fixes their semantics, their generation, and their evolution.
**Event kinds owned:** 3000–3999 (persisted), 90000–90099 (ephemeral).
**ActionTypes owned:** `MOVE_TO`, `IDLE`, `SLEEP`, `EAT` (`02-ARCHITECTURE.md §6.2`).
**Depends on:** `02-ARCHITECTURE.md` (§4 determinism, §5 tick loop, §5.1 resolution order, §7.1 dependency rules, §8.1 `MECHANISM`), `03-DATA-MODEL.md §3`, `04-AGENT-SPEC.md` (§5 perception, §7 salience, §8 reflex, §11 validation).
**Adds no new tables.** Two additive indexes (§5.3) and two additive vocabulary values (§4.1) are the whole schema delta.

## 1. Why a grid earns its cost

The grid is a research instrument. It is not a renderer, and `01-PRD.md §N3` is binding: sprites and animation are out of scope. The grid exists to produce exactly three primitives, and every downstream consumer uses only these:

| Primitive | Consumer | Research question it serves |
|---|---|---|
| `district_id` of an agent's home | rent, school quality, crime exposure, mortality gradient | A2 (inequality sources), B4 (precarity → radicalisation) |
| `place_id` shared by two agents at a tick | `Observation.co_located`, `SAY` legality, `social` salience term | B1, B2, B3 (norms, coalitions, diffusion) |
| `travel_ticks(a, b)` | commute burden, job accessibility, housing choice | A1 (labour matching frictions), A2 |

**What the grid buys that an abstract institutional graph does not.** Without space, the social graph is generated by a preferential-attachment rule and homophily is a *parameter you set*. With space, who you meet is a consequence of where you can afford to live and where you work — so homophily is a *measurement*, and the causal path from income to network position to income is present in the model rather than assumed. That path is the whole of A2 and half of B4. It is the single justification for this subsystem.

**What the grid deliberately does not buy.** No continuous physics, no collision, no line of sight, no per-tile agent rendering in the engine, no weather (§8.5), no vehicles, no road congestion (§5.6). Each of those would add a mechanism whose `entails` string would eat into what we can claim is emergent, in exchange for realism nobody is measuring.

**Normative consequence (the zone-mode enabler).** Tile coordinates are private to `polis/world/grid.py`. No module outside `polis/world/` may import the tile array, and no `Observation` ever contains `(x, y)`. Agents reason about places and districts; `agents.pos_x` / `agents.pos_y` exist for the Observatory and for nothing else. Any institutional code that reads a coordinate is a bug. This rule is what makes §10 a config change rather than a rewrite.

## 2. Grid generation

Deterministic, seeded, and reproducible: `(config, seed) → world_hash`. Generation happens once, at tick 0, before any agent exists. All randomness is drawn from `rng.get("world.gen.<stage>", <key>, None)` per `02-ARCHITECTURE.md §4.1`; the tick argument is `None` because generation is outside the tick loop.

Districts are **axis-aligned rectangles**. This is forced, not stylistic: `districts.bbox INT4RANGE[]` is the authoritative geometry in `03-DATA-MODEL.md §3.1` and `tiles` carries no `district_id` column, so tile → district must be an O(1) rectangle test. Irregular (Voronoi) districts would require a schema change and buy nothing measurable.

### 2.1 Algorithm

```
INPUT  width, height, n_districts, places_per_district, water_fraction,
       road_density, housing_slack, seed
OUTPUT tiles[], districts[], places[], place_paths[]
```

1. **Terrain base.** Allocate `terrain[width][height] = 0` (walkable). Namespace `world.gen.terrain`.
2. **Water.** Draw one river: pick an edge entry point and an exit point on a different edge, walk a bounded random path between them with a per-step lateral jitter, dilate to width `w ∈ [3,6]`. Set `terrain = 3`. Add lakes until the water share reaches `water_fraction` (default 0.06). Water is impassable.
3. **Blocked terrain.** Set `terrain = 1` on a seeded blue-noise scatter covering `blocked_fraction` (default 0.03) of remaining land. This exists so that Manhattan distance ≠ path distance, which is what makes accessibility a non-trivial variable.
4. **District partition.** Recursive binary space partition of `[0,width) × [0,height)` into `n_districts` rectangles. Split axis alternates; split position is drawn uniformly from the middle 50% of the current extent; the largest-area leaf is always split next (deterministic ordering by `(-area, x0, y0)`). Write `districts.bbox = ARRAY[int4range(x0,x1), int4range(y0,y1)]`.
5. **Archetype assignment.** Rank districts by `-(area_weighted_centrality)` where centrality is inverse Chebyshev distance from the grid centre. Assign archetypes in the fixed order `core, uptown, midtown, industrial, suburb, periphery` (§3.1), cycling if `n_districts > 6`. The core district is always the most central; the industrial district is always the one with the greatest water frontage (ports are on rivers).
6. **Arterial roads.** Build a Euclidean minimum spanning tree over district centroids plus the core centroid. Render each MST edge as an L-shaped corridor (horizontal then vertical, corner chosen by the lower `(y, x)` tuple) of width 3, `terrain = 2`. Where a corridor crosses water, the crossing tiles become `terrain = 2` (a bridge). Add one ring road at 0.7× the half-extent.
7. **Local streets.** Within each district, lay a street lattice with spacing `s = round(1 / road_density)` (default 9) aligned to the district origin, `terrain = 2`, skipping water. This is the only source of intra-district accessibility variation, and it is uniform by design: within-district texture is not a research variable.
8. **Place siting.** For each district, take its archetype's place-mix quota (§4.2, sums to `places_per_district`). For each `(type, n)` in a fixed type order, site `n` places by: sample candidate tiles adjacent to a `terrain = 2` tile and at least `min_place_separation` (default 4) tiles from every already-sited place; score candidates by `road_adjacency × 2 + centrality`; take the best, breaking ties by `(y, x)`. Write `places` rows with `place_id = "pl_" || zero_padded_index`, `capacity` per §4.2, `open_hours` per §4.3, `owner_id` per §4.4, `rent_cents = base_rent_cents` per §7.2. Set `tiles.place_id`.
9. **Residential sizing.** Draw each `home` place's capacity from its district's dwelling-class mix (§4.2). If `Σ home.capacity < housing_slack × initial_agents` (default 1.15), scale capacities upward by the smallest integer factor that satisfies it. **Place counts are never adjusted** — `|places|` must be a pure function of config so that `|place_paths| = |places|²` is knowable before generation runs.
10. **Connectivity repair.** Compute the connected components of `{terrain ∈ {0,2}}` under 4-adjacency. If more than one component contains a place, carve a straight `terrain = 2` corridor between the two nearest boundary tiles of the two largest such components, and repeat. Assert afterwards that every place is reachable from every other place; failure is a hard error, not a warning.
11. **All-pairs paths.** Dijkstra from each place over the walkable graph with step cost `1` on `terrain = 2` and `offroad_cost` (default 2) on `terrain = 0`, tie-broken on `(cost, y, x)`. Write `place_paths` rows for every ordered pair including `from == to` (`distance = 0, travel_ticks = 0`). `distance` is the unweighted tile count; `travel_ticks` is derived per §5.2. `path` stores **turn-point vertices only** (flattened `[x0,y0,x1,y1,…]`), not every tile — nothing but the renderer reads it, and full tile sequences would cost ~96 MB against ~6 MB for turn points. Runs in a process pool (`02-ARCHITECTURE.md §4.3`: pure compute, returns values, mutates nothing). Assert symmetry: `travel_ticks(a,b) == travel_ticks(b,a)`.
12. **Initial district metrics.** Seed `land_value_cents`, `school_quality`, `amenity_score` from the archetype table (§3.1); set `crime_rate = archetype_base`. These are starting conditions only — every one of them is endogenous from tick 1 (§3.2–§3.6).
13. **Seal.** Compute `world_hash = sha256(canonical(tiles) ‖ canonical(districts) ‖ canonical(places) ‖ canonical(place_paths.travel_ticks))`. Emit `WORLD_GENERATED` (3100) and `PATHS_PRECOMPUTED` (3101). Mark the tile array read-only (`ndarray.flags.writeable = False`) for the life of the process.

### 2.2 Reproducibility

`world_hash` is recorded in the `WORLD_GENERATED` payload and checked on `--resume` and on replay. A mismatch halts. `tests/determinism/test_world_generation.py` regenerates the world 20× from the same seed and asserts a single distinct hash; it also asserts that two different seeds produce different hashes (a generator that ignores its seed passes the first test trivially).

| `midtown` | 310_000 | 0.60 | 0.028 | 0.64 | Mixed. The default. |
| `industrial` | 95_000 | 0.34 | 0.055 | 0.22 | Factories, studios, port. Cheap and loud. |
| `suburb` | 240_000 | 0.71 | 0.012 | 0.58 | Family housing, schools, long commutes. |
| `periphery` | 70_000 | 0.28 | 0.075 | 0.18 | Cheapest housing, thinnest services. |

### 3.2 `MECHANISM world.rent_response` — rent responds to demand

Fires **PHASE 7**, sim-weekly. All arithmetic in basis points and cents; no floats touch money (`02-ARCHITECTURE.md §4.6`).

```
v_d      = vacant_units(d) / total_units(d)                       # last committed tick
gap_bp   = clamp(10_000 * (target_vacancy - v_d) / target_vacancy, -10_000, +10_000)
delta_bp = clamp(rent_elasticity_bp * gap_bp // 10_000, -rent_step_cap_bp, +rent_step_cap_bp)
rent_index_bp[d] = max(1_000, rent_index_bp[d] + delta_bp)
for p in unleased_homes(d):
    p.rent_cents = max(rent_floor_cents, base_rent_cents[p] * rent_index_bp[d] // 10_000)
```

> `entails:` *Asking rent rises where vacancy is below target and falls where it is above. Therefore: (a) the price of space is monotone in local demand, and (b) given any dispersed income distribution, income-sorting across districts follows arithmetically from the affordability filter in §7.3. No finding about spatial income segregation may be reported as emergent without comparison to `--mechanism-off world.rent_response`, which pins `rent_index_bp` at 10 000.*

### 3.3 `MECHANISM world.crime_response` — crime responds to enforcement and poverty

Fires **PHASE 7**, sim-daily.

```
poverty_share = residents(d) with wealth_cents < poverty_line_cents / residents(d)
enforcement   = police_places(d) * WorldParams.enforcement_intensity / residents(d)
realised      = detected_crimes_in(d, last 7 sim-days) / residents(d)
target        = clamp(k0 + k1*poverty_share - k2*enforcement + k3*realised_norm, 0, 1)
crime_rate[d] += alpha * (target - crime_rate[d])                 # alpha = 0.05
```

`crime_rate` is an **environmental scalar**: it feeds the mortality hazard (`04-AGENT-SPEC.md §12.3`), the housing preference score (§7.3), and `PlaceView.safety`. **It never causes a crime.** Crimes are `COMMIT_CRIME` actions produced by agents and adjudicated in `polis/society/law.py`. If the world could generate crimes from a district scalar, B5 would be circular.

> `entails:` *A negative association between enforcement intensity and district crime_rate, and a positive association between local poverty share and district crime_rate, hold by construction through k1 and k2. B5's deterrence elasticity must therefore be estimated on individual `COMMIT_CRIME` decisions against realised detection probability, never on this scalar. `--mechanism-off world.crime_response` sets `k1 = k2 = 0`, leaving crime_rate a pure lagged mirror of realised crime.*

### 3.4 `MECHANISM world.school_funding` — school quality responds to the local tax base

Fires **PHASE 7**, once per school term (90 sim-days).

```
tax_base_cents  = Σ land_value_cents over buildable tiles in d
per_pupil_cents = (WorldParams.school_levy_bp * tax_base_cents // 10_000) // max(1, pupils(d))
q_target        = clamp(per_pupil_cents / reference_per_pupil_cents, 0.05, 0.95)
school_quality[d] += beta * (q_target - school_quality[d])        # beta = 0.20
for s in schools(d): s.quality = clamp(school_quality[d] * s.quality_offset, 0.01, 0.99)
```

`schools.quality` (`03-DATA-MODEL.md §9`) is written here; skill growth consumes it (`04-AGENT-SPEC.md §3`).

> `entails:` *School quality is monotone in district land value. Combined with §3.2, this implies a positive correlation between parental wealth and child skill attainment. That correlation therefore cannot be reported as emergent intergenerational transmission (A2, B6). The emergent component must be measured against `--mechanism-off world.school_funding`, which funds all schools equally from a central pool at the same total cost. `school_levy_bp` is set by the polity, so this mechanism is also the transmission channel for education-policy shocks (A4).*

### 3.5 `MECHANISM world.land_value` — land value capitalises rent, amenity, and school quality

Fires **PHASE 7**, sim-monthly.

```
quality_bp = 10_000 + w_a*amenity_score[d]*10_000 + w_s*school_quality[d]*10_000
                   - w_c*crime_rate[d]*10_000 + w_x*accessibility_bp[d]
implied_cents = median_rent_cents(d) * capitalisation_multiple * quality_bp // 10_000
land_value_cents[d] += gamma * (implied_cents - land_value_cents[d]) // 100   # gamma as bp
```

`accessibility_bp[d]` is static: `10_000 // (1 + mean travel_ticks from d's places to the core district's places)`. It is the only place where the tile layer enters an economic variable, and it degrades to a district-hop count in zone mode (§10).

> `entails:` *Land value is monotone in amenity and school quality and decreasing in crime. Together with §3.2 and §3.4 this closes a positive feedback loop: shops open → amenity ↑ → land value ↑ → school funding ↑ → demand ↑ → rent ↑ → low-income households leave → poverty share ↓ → crime ↓ → amenity ↑. The **loop** is emergent; every **link** is a tagged mechanism. A gentrification finding must be stated as "the tagged links compose into a displacement cycle at these parameter values", never as "gentrification emerged".*

### 3.6 `MECHANISM world.amenity_response` — amenity responds to the open place mix

Fires **PHASE 7**, sim-weekly.

```
amenity_score[d] = clamp( Σ_t amenity_weight[t] * open_places(d, t) / places(d), 0, 1 )
amenity_weight = {park: +3.0, shop: +1.2, bar: +1.0, school: +0.8, university: +1.5,
                  hospital: +0.6, office: +0.1, home: 0.0, police: +0.3,
                  factory: -1.4, studio: -0.4, shelter: -0.3}
```

This is the endogenous entry point: firms open and close shops, bars, and factories (`06-ECONOMY-SPEC.md`), which moves amenity without any world-level decision.

> `entails:` *Districts where firms open consumer-facing places become more desirable by construction. Business-formation geography therefore drives amenity by definition, not by inference. `--mechanism-off world.amenity_response` freezes `amenity_score` at its generated value.*

All five mechanisms emit their own event kind (§13, 3061–3065) carrying inputs, outputs, and the mechanism id, so the Observatory can attribute any district-level change to the rule that made it.

## 5. Movement

### 5.1 State

Movement state lives entirely in columns that already exist on `agents` (`03-DATA-MODEL.md §2.1`): `current_place_id`, `dest_place_id`, `path_cursor`, `pos_x`, `pos_y`.

```python
# polis/world/api.py
@dataclass(frozen=True, slots=True)
class Location:
    place_id:      str | None    # None ⟺ in transit
    dest_place_id: str | None
    path_cursor:   int | None    # ticks already travelled, 0-based
    travel_ticks:  int | None
    district_id:   str           # district containing the agent, defined in transit too
    x: int; y: int               # RENDER ONLY. Reading these outside polis/world/ is a bug.
```

**Invariant `INV-WORLD-POSITION`** (every tick, HALT): for every living agent, exactly one of
`(current_place_id IS NOT NULL AND dest_place_id IS NULL AND path_cursor IS NULL)` or
`(current_place_id IS NULL AND dest_place_id IS NOT NULL AND 0 <= path_cursor < travel_ticks)`
holds. An agent in neither state has been dropped by the resolver.

### 5.2 `travel_ticks` derivation

```
step_cost   = 1 on terrain 2 (road), offroad_cost (default 2) on terrain 0
path_cost   = Dijkstra cost, precomputed in §2.1 step 11
cost_per_tick = tiles_per_sim_hour (default 150) × sim_hours_per_tick
travel_ticks = clamp(ceil(path_cost / cost_per_tick), 0, max_travel_ticks)
               with travel_ticks = 0 iff from == to
```

At 200×200 tiles and `tile_metres = 25` the city is 5 km across; a cross-city trip costs ~400 weighted units ≈ 3 ticks in `microscope`. `max_travel_ticks` (default 4) caps a journey at a third of a working day; the cap is a declared parameter and its binding rate is reported as `world.travel_cap_binding_share`. In `chronicle`, `sim_hours_per_tick = 24` and every pair collapses to `travel_ticks = 0` (§8.4).

### 5.3 Additive indexes

```sql
-- additive; does not redefine 03-DATA-MODEL.md §3 or §2.1
CREATE INDEX ag_transit ON agents (run_id, dest_place_id) WHERE current_place_id IS NULL;
CREATE INDEX pl_home_vacant ON places (run_id, district_id, rent_cents)
    WHERE type = 'home';
```

### 5.4 Resolution — PHASE 5, step 1

Movement resolves **first** in PHASE 5 (`02-ARCHITECTURE.md §5.1`), because co-location determines what every later institution considers legal.

```python
# polis/world/movement.py
def resolve_movement(actions, W, tick, rng) -> list[Event]:
    ev, arrivals = [], defaultdict(list)          # place_id -> [agent_id]

    # 1. Auto-advance agents already in transit. Not an action; consumes no slot.
    for a in stable(W.in_transit(), key=lambda a: a.agent_id):
        a.path_cursor += 1
        if a.path_cursor >= a.travel_ticks:
            arrivals[a.dest_place_id].append(a.agent_id)

    # 2. Interpret MOVE_TO. Existence, reachability, openness, legality already
    #    checked in PHASE 4 (04-AGENT-SPEC.md §11).
    for act in stable(moves(actions), key=lambda x: x.actor_id):
        a, dst = W.agent(act.actor_id), act.params["place_id"]
        if a.in_transit:
            if dst == a.dest_place_id: continue                      # no-op, keeps going
            ev.append(JOURNEY_ABANDONED(a, a.dest_place_id, a.path_cursor, dst))
            a.origin = W.nearest_place(a.x, a.y)                      # restart from here
            a.clear_journey()
        t = W.travel_ticks(a.origin_place, dst)
        if t == 0: arrivals[dst].append(a.agent_id)
        else:      a.start_journey(dst, t); ev.append(JOURNEY_STARTED(a, dst, t))

    # 3. Admission. The full claimant set is known before any admission, so the
    #    outcome does not depend on the order in which claimants were collected.
    for place_id in sorted(arrivals):
        p, claim = W.place(place_id), arrivals[place_id]
        free = p.capacity - W.occupancy_excluding(place_id, claim)
        ranked = sorted(claim, key=lambda g: (-priority(g, p), lottery(g, p, tick), g))
        for g in ranked[:max(0, free)]:
            W.admit(g, place_id); ev.append(AGENT_MOVED(g, place_id))
        for g in ranked[max(0, free):]:
            ev.append(MOVE_BLOCKED(g, place_id, "full")); W.bounce(g, place_id, tick)

    W.freeze_occupancy(tick)     # everything later in PHASE 5 reads this and only this
    return ev
```

`lottery(g, p, tick) = rng.get("world.admission", f"{p.place_id}|{g}", tick).random()`.

> `MECHANISM world.admission_priority` — priority classes, highest first: **(1)** resident of, owner of, or employed at the place; **(2)** an agent with a `scheduled` obligation there this tick (`04-AGENT-SPEC.md §7`); **(3)** everyone else. Within a class, the seeded lottery decides. `entails:` *Access to scarce space is allocated by tenure and obligation rather than by willingness to pay. Therefore congestion never produces a price, and no finding about queueing, rationing, or access inequality may be attributed to market behaviour. `--mechanism-off world.admission_priority` replaces the classes with a pure lottery.*

**Bouncing.** A blocked traveller holds at `path_cursor = travel_ticks - 1` and retries next tick. After `max_bounce_ticks` (default 3) it emits `AGENT_STRANDED` (3006) and is admitted to the nearest `park` in the destination's district, or the district `shelter` between 22:00 and 06:00. No agent is ever teleported.

### 5.5 Perception in transit

An in-transit agent gets a full `Observation` (`04-AGENT-SPEC.md §5`) with these differences:

| Slice | In transit |
|---|---|
| `place` | `PlaceView(place_id=None, in_transit=True, eta_ticks=travel_ticks - path_cursor - 1, district_id=<current tile's district>)` |
| `co_located` | **empty** |
| `inbox`, `feed`, `news`, `market`, `offers`, `obligations` | unchanged — phones exist |
| legal actions | `MOVE_TO` (retarget), `IDLE`, `NULL_ACTION`, and all `anywhere` actions in §4.4 except `SAY` |
| salience | `scheduled` and `social` terms fire normally; `novelty` is floored at 0 |

**Transit produces no encounters.** This is a modelling decision, not an oversight: co-locating travellers on a shared edge would require an edge-occupancy index rebuilt per tick, would make encounter counts a function of road layout rather than of destination choice, and would add a mechanism to defend. The cost is that weak ties formed in transit (the classic "met on the commute") do not exist, which biases the new-tie rate downward. Recorded as a limitation in §12.

### 5.6 Congestion — explicitly not modelled

Road congestion is **not** in v1. Two reasons, in order of weight:

1. **Determinism and phase discipline.** State-dependent travel time makes `travel_ticks` a function of other agents' same-tick choices, which violates `02-ARCHITECTURE.md §4.4` (simultaneous submission). The only compliant form is a lag on last tick's committed edge loads, which is a different and weaker model.
2. **Cost/benefit.** It converts an O(1) matrix lookup into a per-tick recomputation and adds a mechanism whose `entails` would touch every commute-related finding, in exchange for a phenomenon no research question in `01-PRD.md §3` asks about.

Congestion is therefore replaced by **place capacity** (§5.4), which is the only scarcity the world models and which is resolved order-independently. If congestion is later wanted, the compliant extension is `travel_ticks_effective(a,b,tick) = travel_ticks(a,b) × (1 + congestion_bp[edge_bucket, tick-1] / 10_000)` computed from committed state, behind `world.movement.model_congestion: true`. It is specified here so nobody invents a different one; it is not built (`02-ARCHITECTURE.md §1.8`).

## 6. Co-location and encounter

### 6.1 The occupancy index

At the end of PHASE 5 step 1, `freeze_occupancy(tick)` writes `dict[place_id, tuple[agent_id, ...]]`, each tuple sorted ascending by `agent_id`. It is immutable for the rest of the tick. PHASE 1 of the **next** tick reads it to build `Observation.co_located`, which satisfies `04-AGENT-SPEC.md §5` rule 1 (perception is a pure function of last tick's committed state).

### 6.2 Ranking and the cap of 12

`Observation.co_located` is capped at 12 (`04-AGENT-SPEC.md §5`). The cap forces the ranking question to be explicit, which is the point.

```
rank(o | self) = 3.0 · relationship_strength(self, o)      # 0 if no edge
               + 1.5 · [o is kin or partner]
               + 1.0 · [o is in self's household]
               + 1.0 · [o works at self's employer]
               + 0.8 · [o addressed self last tick]
               + 0.5 · [self has never been co-located with o]
               + 0.3 · prominence(o)                       # wealth pctile, office, followers
               + ε,  ε ~ U(0, colocation_epsilon)          # rng.get("world.colocate", self_id, tick)
```

Ties break on `agent_id` ascending. **Three of the twelve slots are reserved for agents the observer has never been co-located with**, filled before the general ranking; unused reserved slots fall back to the general pool.

> `MECHANISM world.colocation_ranking` — `entails:` *An agent in a crowded place preferentially perceives strong ties, kin, household, and colleagues. Therefore observed homophily in interaction is partly a property of this ranking and not purely of agent choice. `--mechanism-off world.colocation_ranking` replaces the score with a uniform sample of size 12.*

> `MECHANISM world.colocation_novelty_reservation` — `entails:` *Reserving `novel_slots` (default 3) guarantees a floor on new-tie formation opportunity per agent-tick. The rate of new relationship formation is therefore partly a property of this reservation. Any finding about social-network growth must report `novel_slots`, which is swept 0–6.*

The `ε` term is not decoration. Without it a place with 40 occupants shows the same twelve faces forever, no new edge can form, and the social graph freezes at whatever the first tick produced. `colocation_epsilon` defaults to 0.05 in `microscope`.

`COLOCATION_SLICE_TRUNCATED` (3021) is written at `cognition_sample_rate` and records `(present_count, shown_count, dropped_count)` per agent-place. It is the measurement of what the cap hides, and it is what lets a reviewer bound the truncation bias rather than guess at it.

### 6.3 Why this is the payoff

Co-location gates `SAY`, gates every counterparty action in §4.4 that requires the counterparty present, and supplies the `social` term of salience (`04-AGENT-SPEC.md §7`), which is one of five inputs deciding who gets LLM cognition. So the grid determines not only who can talk to whom, but who gets to *think*. That chain — district affordability → home → workplace → co-location → salience → cognition → outcomes → wealth → district affordability — is the causal loop that A2, B3, and B4 are asking about. It exists only because the grid exists.

`FIRST_ENCOUNTER` (3020) is emitted the first time an ordered pair `(a_id < b_id)` shares a place. It is bounded (at most one per pair per run) and is the primary research signal from this subsystem.

## 7. Housing and rent

### 7.1 Representation

No new tables. A dwelling is a `places` row with `type = 'home'`; a tenancy is `households.home_place_id` + `households.tenure` + `households.rent_cents` (`03-DATA-MODEL.md §2.5`).

| Field | Meaning |
|---|---|
| `places.capacity` | resident capacity of the **building** |
| `places.rent_cents` | current **asking** rent per household per sim-month |
| `places.owner_id` | landlord (`ag_`, `hh_`, `fm_`) or `gov` |
| `households.rent_cents` | **contracted** rent, sticky until lease renewal |
| `households.tenure` | `own` \| `rent` \| `shelter` |

A building is *vacant for a household* if `Σ members of households homed there + incoming household size ≤ capacity`.

### 7.2 Rent setting

`base_rent_cents[p] = land_value_cents[d] × capacity × rent_yield_bp // (10_000 × residents_per_household_norm)`, fixed at generation. Asking rent is `base_rent_cents × rent_index_bp[d] // 10_000`, updated by `world.rent_response` (§3.2).

> `MECHANISM world.lease_stickiness` — a sitting tenant's `households.rent_cents` is unchanged until `lease_ticks` (default one sim-year) elapse, then resets to the current asking rent via `LEASE_RENEWED` (3088). `entails:` *Incumbent tenants face lower rent than new entrants in a rising market. Therefore an insider/outsider gap in housing cost, and reduced mobility among incumbents, hold by construction. `--mechanism-off world.lease_stickiness` sets `lease_ticks = 1`, repricing every tenancy every tick.*

### 7.3 Allocation — PHASE 7, sim-weekly

```python
def housing_step(W, params, tick, rng):
    pool = [h for h in W.households() if move_trigger(h, tick)]
    #   move_trigger: newly formed | dissolved | evicted | in shelter
    #                | rent_cents > affordability_cap_bp * income // 10_000
    #                | commute burden > commute_tolerance_ticks
    #                | income doubled since last move (upgrade)
    for _ in range(params.search_rounds):                 # default 4
        offers = defaultdict(list)
        for h in stable(pool, key=lambda h: h.household_id):
            cands = [p for p in W.vacant_homes_for(h)
                     if p.rent_cents <= affordability_cap_bp * h.income_cents // 10_000]
            if not cands:
                emit(HOUSING_SEARCH_FAILED(h)); continue
            best = max(cands, key=lambda p: (score(h, p), -p.rent_cents, p.place_id))
            offers[best.place_id].append(h)
        for place_id in sorted(offers):                   # landlord picks
            winner = max(offers[place_id],
                         key=lambda h: (h.offered_rent_cents, h.income_cents, h.household_id))
            W.allocate(winner, place_id); emit(HOME_ALLOCATED(...)); pool.remove(winner)
    for h in pool: W.to_shelter(h); emit(HOMELESSNESS_ENTERED(h))

score(h, p) = w_afford · (1 - p.rent_cents / budget_cents)
            + w_school · school_quality[p.district]        · has_children(h)
            + w_safety · (1 - crime_rate[p.district])
            + w_amenity · amenity_score[p.district]
            - w_commute · mean(travel_ticks(p, anchor) for anchor in h.work_and_school_places)
            + ε,  ε ~ U(0, 0.03)   # rng.get("world.housing", h.household_id, tick)
```

Deferred acceptance over rounds, not a sequential walk, so the outcome does not depend on household iteration order.

> `MECHANISM world.housing_match` — `entails:` *Households are allocated to the affordable dwelling maximising a fixed weighted score over rent, school quality, safety, amenity, and commute. Therefore district sorting by income, by presence of children, and by workplace location follows analytically from the income distribution and this score. **This is the strongest confound in the world module.** No claim about residential sorting, school segregation, or neighbourhood effects may be made without the `--mechanism-off world.housing_match` baseline, which allocates uniformly at random among affordable vacancies.*

### 7.4 Eviction

```
arrears_cents accrues in the economy's rent settlement (§9.3) and is reported back to the world.
arrears_cents > eviction_arrears_months × households.rent_cents
    → EVICTION_ISSUED (3085), effective_tick = tick + eviction_grace_ticks (default 1 sim-month)
    → at effective_tick, if arrears not cleared: LEASE_ENDED (3045),
      HOUSEHOLD_DISPLACED (3086) → re-enter the search pool at the next housing step
    → if the search fails: HOMELESSNESS_ENTERED (3089), tenure = 'shelter'
```

### 7.5 Homelessness

A homeless household's `home_place_id` points at its district `shelter`, `tenure = 'shelter'`, `rent_cents = 0`. `households.home_place_id` stays `NOT NULL`, so no schema change is needed. Consequences are physical only: reduced sleep restoration (§4.5), reduced food restoration, and the shelter's `crime_rate` and `amenity_score` exposure. **The world imposes no employment, reputation, or social penalty on homelessness.** If it did, the finding "homelessness reduces re-employment" would be a restatement of the rule.

### 7.6 Tie to household formation

Household formation and dissolution are owned by `polis/agents/demography.py` (kinds 15000–15999). The world exposes `find_home(members, budget_cents, anchor_place_ids) -> place_id | None` and nothing more. If a newly formed household cannot be homed, `HOUSEHOLD_FORMED` still fires and the new household co-resides in one partner's existing building until the next housing step, consuming that building's capacity. Housing scarcity therefore feeds back into fertility and partnering pressure without the world containing a fertility rule.

## 8. Time-of-day and weekly rhythm

### 8.1 Calendar

`ticks_per_sim_day = 24`, `days_per_sim_year = 360`, month = 30 days, week = 7 days floating (`weekday = sim_day % 7`; days 5 and 6 are rest days). A 360-day year does not align with a 7-day week, exactly as the 360-day actuarial convention does not. All cadences are expressed in sim-time and converted by the scheduler (`02-ARCHITECTURE.md §5.2`).

### 8.2 The rhythm is an outcome, not a rule

The only rules are `PLACE_SCHEDULE` (§4.3), employment contracts (`06-ECONOMY-SPEC.md`), school terms, and the reflex destination policy below. The daily population distribution that emerges from them is a **measurement**, reported as `world.occupancy_entropy` and the district-level flow matrix.

> `MECHANISM world.reflex_destination` — a REFLEX agent's `MOVE_TO` target is chosen by: (1) if a mandatory obligation is scheduled within `travel_ticks` of now, go there; (2) else if a need is below its threshold and a legal restoring place is reachable, go to the nearest one; (3) else if within work/school hours and employed/enrolled, go to the workplace/school; (4) else go home. `entails:` *Employed reflex agents execute a home → work → home daily cycle and enrolled agents a home → school → home cycle. Therefore the observed daily rhythm, the modal commute count, and the shape of the time-use distribution are implied by this policy and not emergent. Every time-use or commuting finding must be stated relative to the `--reflex-only` baseline (threat T9).*

### 8.3 Commuting

`commute_ticks(agent) = 2 × travel_ticks(home_place, employer.place_id)` per work day. It enters the housing score (§7.3), the `energy` decay, and the metric `world.mean_commute_ticks`. `world.unreachable_job_share` reports the fraction of open vacancies whose place is more than `max_travel_ticks` from the applicant's home — if that number is large, measured unemployment is a grid artefact, not a labour-market result (§12).

### 8.4 `microscope` vs `chronicle`

In `chronicle`, one tick is one sim-day. **`MOVE_TO` stops meaning "begin a journey to P" and starts meaning "spend this day primarily at P".** Everything below follows from that.

| Concept | `microscope` (1 tick = 1 h) | `chronicle` (1 tick = 1 d) |
|---|---|---|
| `MOVE_TO` semantics | begin a journey | choose the day's location |
| `travel_ticks` | 0–4 | always 0 |
| in-transit state | occurs | **never occurs**; `dest_place_id` and `path_cursor` are always NULL |
| spatial friction | paid in ticks | paid in money and energy (below) |
| `capacity` | instantaneous stock | daily flow: `capacity × chronicle_turnover` (default 6) |
| `open_hours` | enforced per hour | reduced to "open at all on this weekday" |
| `co_located` | who is here this hour | who was here today |
| `colocation_epsilon` | 0.05 | 0.15 — a day at a place is many encounter opportunities, not one |
| `SLEEP` | an explicit 6–8 tick block | auto-resolved at end of tick (below) |
| `EAT` | per tick | one settlement per day |
| housing / rent / district steps | sim-weekly, sim-daily, sim-monthly | **identical** — cadences are sim-time |

> `MECHANISM world.chronicle_commute_cost` — under `chronicle`, distance costs `commute_cost_cents = distance_tiles × fare_per_tile_cents` plus `energy -= distance_tiles × chronicle_energy_per_tile`, charged once per work day. `entails:` *Without this, `chronicle` deletes spatial friction entirely and district sorting collapses to a pure amenity-and-price problem. The rule guarantees distance still enters the housing decision, which means commute-related findings are **not** comparable across clock profiles without reporting `fare_per_tile_cents`. Any cross-profile comparison must show the result under both.*

> `MECHANISM world.chronicle_nightly_return` — under `chronicle`, a housed agent ends every tick at its household's home place unless it submitted an explicit `SLEEP` elsewhere. `entails:` *Household members are guaranteed to be co-located once per day. Therefore intra-household interaction frequency, and any finding depending on it (belief transmission from parent to child, B6), is partly implied by this rule. `--mechanism-off world.chronicle_nightly_return` leaves agents where their last action put them.*

### 8.5 Weather

Not in v1. Weather is a global time-varying covariate that would enter mood, movement, and consumption, requiring three mechanisms and a defence of each, in exchange for a phenomenon no question in `01-PRD.md §3` asks about. `00-INDEX.md` lists it in this document's scope; this is the disposition of it. If it is ever added it belongs here, as a `WorldParams` field and one `MECHANISM`.

## 9. World services

### 9.1 The public API

`polis/world/api.py` is the only surface other modules may import. Per `02-ARCHITECTURE.md §7.1`, `world → kernel, events, config` and nothing else; `agents`, `economy`, and `society` import `world`.

```python
class World(Protocol):
    # static topology, immutable after generation
    def place(place_id) -> Place; places_of_type(type, district_id=None) -> tuple[Place, ...]
    def district(district_id) -> District; district_of(place_id) -> str
    # routing — O(1) matrix lookup, never A*

    # live state — reflects the last committed tick only
    def occupants(place_id) -> tuple[str, ...]; occupancy(place_id) -> int
    def free_capacity(place_id) -> int; is_open(place_id, tick) -> bool
    def location_of(agent_id) -> Location; place_view(agent_id, tick) -> PlaceView
    def co_located(agent_id, tick, cap=12) -> tuple[str, ...]

    def find_home(members, budget_cents, anchors) -> str | None

    def close_place(place_id, reason) -> None
```
*(Signatures elided to one line per group; the real file is fully annotated.)*

`create_place` is the only runtime topology change (a firm opening a shop). It sites the place by §2.1 step 8, runs **one** Dijkstra to fill the new row and column of the all-pairs matrix, emits `PLACE_CREATED` (3040), and preserves `|place_paths| == |places|²`. Runtime place creation outside this function is a bug and is caught by `INV-WORLD-PATHS`.

### 9.2 `WorldParams`

Policy inputs to §3's mechanisms. The world cannot import `polis.society`, so these live in a kernel-owned parameter object updated from `POLICY_ENACTED` (12030); the world reads it and emits `WORLD_PARAMS_CHANGED` (3103) when a value it consumes changes.

| Field | Consumer | Set by |
|---|---|---|
| `enforcement_intensity` | §3.3 | polity / police budget |
| `school_levy_bp` | §3.4 | polity / education policy |
| `rent_control_cap_bp` | §3.2 (caps `delta_bp`) | polity |
| `infrastructure_spend_cents` | §9.4 | polity |
| `poverty_line_cents` | §3.3 | polity |

### 9.3 Money: the world computes, the economy posts

The world **never** writes a ledger entry. It cannot: `03-DATA-MODEL.md §4.2` rule 4 restricts ledger writes to `polis/economy/ledger.py`, and §7.1 forbids `world → economy`. The protocol is:

```
PHASE 7 · step W1 (world)     emit RENT_DUE (3083) {payer_id, place_id, owner_id, amount_cents,
                                                    period_start_tick, period_end_tick}
PHASE 7 · step E2 (economy)   drain this tick's RENT_DUE, post balanced legs with reason='rent',
                              report arrears back via the arrears buffer
PHASE 7 · step W3 (world)     read arrears, run §7.4 eviction, run §3.2–§3.6 mechanisms
```

PHASE 7 steps are sequential and their order is fixed here; no step reads a state change made by a later step in the same tick.

### 9.4 Land ownership and public infrastructure

`places.owner_id` is authoritative. `gov` is a reserved singleton owner id — it is not an entity prefix and never appears where an `ag_`/`fm_`/`bk_` id is expected. Public places (`school`, `university`, `park`, `police`, `hospital`, `town_hall`, `courthouse`, `exchange`, `shelter`) are `gov`-owned and pay no rent. Transfers of ownership emit `PLACE_OWNER_CHANGED` (3042); a firm taking a commercial place signs a lease (`LEASE_SIGNED`, 3044) and the world emits `RENT_DUE` against it exactly as for a household. `infrastructure_spend_cents` funds `INFRASTRUCTURE_BUILT` (3102) — new `gov` places, sited by §2.1 step 8. Speculative land trading between agents is out of scope for v1; `PLACE_OWNER_CHANGED` exists so it can be added without a schema change.

## 10. Degradation: zone-only mode

`01-PRD.md §11` names "grid is a distraction — movement engineering consumes M1" as a medium risk whose mitigation is a clean degradation to zone-only mode. This is that mode. Setting `world.mode: zone` is a **config change**; no module outside `polis/world/` is modified, because §1's normative rule guarantees no module outside `polis/world/` ever touched a tile.

| Component | `grid` | `zone` |
|---|---|---|
| `tiles` | generated, ~40 000 rows | **not generated**, table empty |
| §2.1 steps 1–3, 6, 7, 10, 11 | run | **skipped** |
| `districts.bbox` | BSP rectangles | synthetic unit rectangles, adjacency from a seeded ring-plus-chord graph |
| `places.x`, `places.y` | real | district index and slot index, for layout only |
| `place_paths.distance` | tile count | district hop count × 100 |
| `place_paths.travel_ticks` | §5.2 | `0` same district, `1` adjacent, `2` otherwise; `0` in `chronicle` |
| `place_paths.path` | turn points | `'{}'` |
| `accessibility_bp` (§3.5) | mean travel ticks to core | hop count to core |
| Observatory map (§11) | tile raster | district cartogram |
| §3 districts and all five mechanisms · §4 places, hours, affordances · §5.4 capacity and admission · §6 co-location · §7 housing (commute term reads hops) · §8 clock | | **all unchanged** |

**What is lost:** within-district spatial texture, walkability, accessibility as a continuous variable, and the tile map view.
**What is preserved:** every primitive in §1 — district membership, place-level co-location, and a distance metric — and therefore every research question in `01-PRD.md §3` that depends on the world. Spatial inequality is a district-level phenomenon; encounter locality is a place-level phenomenon; neither needs tiles.

**Cut criterion:** if C0x's grid generation and pathfinding work exceeds its M1 budget by more than 50%, cut to `zone` for M1 and revisit at M4. Generation drops from ~13 steps to 5 and `place_paths` from a Dijkstra sweep to a table lookup. Findings produced in `zone` mode must report `world.mode` alongside the seed.

### 13.1 ActionType request

v1.0 of this module needs **no new `ActionType`**; `MOVE_TO`, `IDLE`, `SLEEP`, `EAT` are sufficient.

One addition is **formally requested for M2**, not taken unilaterally: **`RENT_HOME { place_id, offered_rent_cents }`**, group `world`. Justification: §7.3 allocates housing by a deterministic scored matcher, which by `04-AGENT-SPEC.md §8` is exactly the class of decision that must be LLM-only — it has a counterparty, a price, and a commitment. `world.housing_match` is therefore the strongest confound in this module (§7.3) and a placeholder for an agent decision. Until `RENT_HOME` exists, every residential-sorting result must be reported against `--mechanism-off world.housing_match`. Adding it requires a spec change to `02-ARCHITECTURE.md §6.2` and a validator, per that section's rule.

## 15. Mechanism register

Every hard-coded behavioural rule in this module, its ablation, and where its `entails` string is written in full. `--mechanism-off <id>` is the ablation switch in all cases.

| `mechanisms:` key → implementation | Fires | § | Ablation behaviour |
|---|---|---|---|
| `world.rent_response: demand_vacancy_ewma` | PHASE 7, weekly | 3.2 | `rent_index_bp` pinned at 10 000 |
| `world.crime_response: enforcement_poverty_realised` | PHASE 7, daily | 3.3 | `k1 = k2 = 0`; crime_rate mirrors realised crime only |
| `world.school_funding: local_land_value` | PHASE 7, per term | 3.4 | equal per-pupil funding from a central pool, same total |
| `world.land_value: rent_capitalisation` | PHASE 7, monthly | 3.5 | land value frozen at generated value |
| `world.amenity_response: open_place_mix` | PHASE 7, weekly | 3.6 | amenity frozen at generated value |
| `world.admission_priority: tenure_then_lottery` | PHASE 5, step 1 | 5.4 | pure lottery, no priority classes |
| `world.colocation_ranking: tie_strength_plus_novelty` | PHASE 1 | 6.2 | uniform sample of size `cap` |
| `world.colocation_novelty_reservation: reserve_3` | PHASE 1 | 6.2 | `novel_slots = 0` |
| `world.housing_match: deferred_acceptance_scored` | PHASE 7, weekly | 7.3 | uniform random among affordable vacancies |

Fourteen rules, of which five produce district- or network-level correlations directly. That is the honest accounting of how much of this module's output is structure rather than behaviour, and it is why §12's W10 is the failure mode most likely to reach a paper.
